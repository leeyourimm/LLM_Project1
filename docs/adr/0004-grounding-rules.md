# ADR 0004: 근거 규칙 (번호 인용, 근거 없는 요약 문장 버리기, 코드 계산, 확인 안 된 숫자 표시)

- 상태: 채택
- 관련 코드: `src/dartrag/answer/prompt.py`, `answer/service.py`(`check_citations`, `check_numbers`), `answer/numbers.py`, `finance/`, `changes/summary.py`(`parse_summary`, `metric_changes`)

## 맥락
- 공시 서비스에서 틀린 숫자는 답이 없는 것보다 나쁘다. 작은 로컬 모델(ADR 0002)은 자릿수·단위를 자주 틀리고, 계산을 맡기면 더 틀린다.
- 사용자가 답을 믿을 수 있으려면 문장마다 어디에서 왔는지 바로 열어 볼 수 있어야 한다.
- "인용이 문장을 뒷받침하는지"를 LLM 으로 다시 판정하면 느리고 흔들린다 (ADR 0007).

## 결정
1. **번호 인용**: 검색 발췌에 `[1]`, `[2]` 번호를 붙여 `<source>` 태그 안에 넣고, 사실 문장마다 번호를 달게 한다. 없는 번호를 인용하거나 인용이 하나도 없으면 경고를 붙인다. 근거가 없으면 "제공된 공시에서 답을 찾지 못했습니다." 로만 답하게 한다.
2. **변경점 요약은 근거 없는 문장을 버린다**: 코드가 찾은 추가·삭제·수정 문장에 번호를 붙여 주고, 요약 문장에 근거 번호가 없거나 없는 번호를 달면 그 문장은 화면과 알림에 내보내지 않는다 (`parse_summary` 의 `dropped`).
3. **숫자는 코드가 계산한다**: 재무 질문은 재무 DB 에서 값을 찾고 증감률·비율을 코드로 계산해 "재무 데이터" 출처로 첫 번째에 넣는다. 프롬프트는 그 값을 그대로 쓰고 다시 계산하지 말라고 한다. 변경점 요약의 매출·이익 변화도 모델이 아니라 재무 데이터로 계산한다.
4. **확인 안 된 숫자 표시**: 답변 문장마다 금액·비율을 뽑아, 그 문장이 인용한 원문과 조·억·백만원 단위를 환산해 대조한다. 답에 적힌 자릿수만큼 반올림을 허용하고, 원문에 없으면 오류가 아니라 "확인되지 않은 숫자"로 표시한다 (계산값일 수도 있으므로).
5. 원문이 `<source>`·`<item>` 태그를 닫거나 열어 지시를 끼워 넣지 못하게, 대소문자·공백을 바꾼 태그까지 무력화한다.

## 결과와 트레이드오프
- 화면에서 `[1]` 을 누르면 원문이 펼쳐지고, 의심스러운 숫자는 경고로 보인다. 경고 비율은 평가(`max_unverified_number_rate`)와 지표(`dartrag_answer_warnings`)로 추적한다.
- 숫자 대조는 표기만 본다. 값이 맞아도 다른 연도·다른 계정의 숫자를 옮긴 경우는 잡지 못한다.
- 인용이 문장 내용을 실제로 뒷받침하는지(NLI)는 검사하지 않는다. 출처 정확도는 평가셋의 근거 위치로만 잰다.
- 변경점 요약에서 문장을 버리면 내용이 짧아질 수 있다. 정확도를 우선한다.
