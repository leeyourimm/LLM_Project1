# ADR 0003: 하이브리드 검색 (Qdrant dense + OpenSearch nori BM25), bge-m3 와 리랭커

- 상태: 채택
- 관련 코드: `src/dartrag/search/` (`hybrid.py`, `vector.py`, `keyword.py`, `embeddings.py`, `rerank.py`)

## 맥락
- 공시 질문에는 뜻으로 찾아야 하는 것("환율 위험을 어떻게 관리하나")과 낱말이 정확히 맞아야 하는 것("HBM", "유상증자", 계정 이름, 숫자)이 섞여 있다. 벡터 검색만으로는 고유명사·숫자를, 키워드 검색만으로는 바꿔 말한 표현을 놓친다.
- 한국어는 조사가 붙어 공백 단위 BM25 가 잘 안 맞는다. 형태소 분석이 필요하다.
- 비교 질문에서 문서가 많은 회사가 결과를 독차지하고, 해마다 반복되는 문단이 상위를 채우는 문제가 있었다.
- 외부 API 없이 내 서버에서 돌아야 한다 (ADR 0002 과 같은 이유).

## 결정
- dense: bge-m3(다국어, 자체 호스팅) 임베딩을 Qdrant 에 저장한다.
- 키워드: OpenSearch 의 nori 형태소 분석기(`decompound_mode: mixed`, 품사 필터)로 BM25 검색한다.
- 두 결과는 점수 대신 순위로 합친다 (RRF, k=60, 각 50개 후보). 척도가 다른 점수를 정규화할 필요가 없다.
- 회사·연도·보고서 종류 필터를 검색 전에 걸고, 회사가 여럿이면 회사마다 따로 찾아 번갈아 섞는다.
- 해마다 같은 문단은 가장 최근 것만 남기고, 상위 30개를 cross-encoder 리랭커(bge-reranker-v2-m3)로 다시 매긴 뒤, 관련도가 같으면 최신 보고서를 앞에 둔다 (`RECENCY_WEIGHT`).
- 답변 근거에는 같은 섹션의 앞뒤 문단을 붙여 맥락을 넓힌다.
- 청크 원문과 메타데이터의 기준은 Postgres 이고, Qdrant·OpenSearch 는 다시 만들 수 있는 색인이다 (ADR 0005).

## 결과와 트레이드오프
- 고유명사·숫자 질문과 바꿔 말한 질문 모두에서 근거를 찾는다. 검색 적중률은 평가의 `retrieval_hit_rate` 로 계속 잰다.
- 검색 서비스가 둘이라 운영할 것이 늘고(메모리: OpenSearch 1GB 힙, bge-m3 약 2.3GB, 리랭커 추가), 색인 일관성을 `index_version`·`index_model` 로 관리해야 한다.
- 리랭커는 CPU 에서 느리므로 `RERANK_MODEL` 을 비워 끌 수 있다. 끄면 정확도가 조금 떨어진다.
- 설계서의 sparse 벡터, 질의 분해는 아직 넣지 않았다. 평가 결과로 필요가 확인되면 추가한다.
