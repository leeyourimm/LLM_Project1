# ADR 0007: LLM 채점 대신 규칙 채점과 배포 기준(release gate)

- 상태: 채택
- 관련 코드: `src/dartrag/eval/` (`grading.py`, `generate.py`, `gate.py`), `eval/manual.jsonl`, `eval/release_criteria.toml`, `.github/workflows/ci.yml`

## 맥락
- 프롬프트, 모델, 검색 설정을 바꿀 때마다 답변이 나아졌는지 나빠졌는지 숫자로 알아야 한다.
- 흔히 쓰는 LLM 채점(LLM-as-judge)은 로컬 모델(ADR 0002)로 하면 같은 답에도 점수가 흔들려 회귀 검사로 쓰기 어렵고, 상용 모델로 하면 비용과 외부 전송이 생긴다.
- 숫자 문항은 정답이 재무 DB 에 있어서 사람이 일일이 쓰지 않아도 만들 수 있다.

## 결정
- 문항은 JSONL 로 관리한다. 직접 쓴 서술형·답 없음·적대적 문항(`eval/manual.jsonl`)과, 재무 DB 와 계산기로 정답이 확실한 숫자 문항을 자동으로 만든다 (`dartrag eval generate`).
- 규칙으로 채점한다: 검색 적중(근거 위치), 정답 숫자 포함(단위 환산 후), 핵심 키워드, 출처 표시, 없는 출처 인용, 확인 안 된 숫자, 답 없는 질문에 "못 찾음"으로 답했는지, 적대적 질문을 거절했는지, 걸린 시간.
- 배포 기준은 `eval/release_criteria.toml` 에 둔다 (예: 전체 통과율 80%, 숫자 문항 85%, 적대적 문항 95%, 직전 기준선보다 3%p 넘게 떨어지면 실패). 실제 평가는 Ollama 와 데이터가 필요해 CI 에서 돌리지 않고, 결과를 `eval/baseline.json` 으로 올린다. CI 는 `dartrag eval ci-check` 로 기준선이 기준을 넘는지, 현재 `PROMPT_VERSION` 으로 잰 것인지 확인한다.
- 일요일 새벽 정기 평가(`EVAL_SCHEDULE_ENABLED`)가 결과를 `eval_runs` 에 쌓아 대시보드에 품질 추이를 보여 준다. 사용자 👎 평가는 `dartrag feedback export` 로 평가셋 후보가 된다.

## 결과와 트레이드오프
- 같은 답에는 늘 같은 점수가 나와서 회귀를 바로 잡는다. 비용이 없고 데이터가 밖으로 나가지 않는다.
- 서술형 답의 품질(요약이 잘 됐는지, 논리가 맞는지)은 키워드와 근거 위치로만 보므로 거칠다. 사람 샘플 검수로 보완해야 한다.
- 기준선은 사람이 평가를 돌려 올려야 하므로, 프롬프트를 바꾸고 기준선을 다시 재지 않으면 CI 가 막는다 (의도한 동작).
