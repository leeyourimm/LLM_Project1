# ADR 0008: Next.js 화면을 추가하고 기존 정적 화면도 유지

- 상태: 채택
- 관련 코드: `frontend/` (Next.js, Tailwind), `src/dartrag/web/static/` (정적 HTML·JS), `frontend/next.config.ts`

## 맥락
- 처음 화면은 Node 설치 없이 `dartrag serve` 만으로 열리도록 FastAPI 가 정적 HTML·JS 한 벌을 내보냈다. 혼자 내 컴퓨터에서 쓰기에는 가장 간단하다.
- 공개 서비스로는 화면이 많아졌다 (대화, 회사 대시보드, 비교, 피드, 관심 종목·알림, 변경점, 계정, 약관). 정적 JS 한 파일로는 유지보수가 어렵고, 접근성·다크 모드·모바일 대응을 일관되게 하기 힘들다.
- 백엔드 API 는 이미 화면과 분리돼 있다 (`/api/*`).

## 결정
- 공개용 화면은 `frontend/` 의 Next.js(App Router)와 Tailwind 로 만든다. 서버 렌더링 대신 대부분 클라이언트 화면이고, 데이터는 모두 같은 출처의 `/api` 로 받는다.
- 개발 때는 Next 가 `/api` 를 FastAPI 로 넘기고(`API_ORIGIN`), 배포 때는 리버스 프록시가 `/api` 는 FastAPI 로, 나머지는 Next 로 보낸다. 그래서 쿠키는 같은 출처로 오가고 CORS 를 열 필요가 없다. 다른 주소에서 띄울 때만 `ALLOWED_ORIGINS` 를 쓴다.
- 기존 정적 화면은 지우지 않는다. `dartrag serve` 만으로 내 컴퓨터에서 쓰는 사람을 위해 그대로 둔다. 새 기능은 Next 화면에 먼저 넣는다.
- 보안 헤더는 API 응답은 FastAPI 가, 화면 응답은 Next 설정(`headers()`)이 붙인다.

## 결과와 트레이드오프
- 공개 화면의 품질(접근성, 차트, 스트리밍 답변)을 올리기 쉬워졌고, CI 가 타입 검사·테스트·빌드를 따로 돌린다.
- 화면이 두 벌이라 기능 차이가 생긴다 (계정 삭제·내 데이터 내려받기 같은 새 기능은 Next 화면에만 있다). 정적 화면은 점차 "로컬 전용 간이 화면"으로 줄인다.
- Next 화면의 스크립트 CSP 는 배포 시 Caddy 가 요청마다 만든 nonce 로 건다. 그래서 화면을 미리 만들어 두지 않고 요청마다 그린다. next.config 는 클릭재킹·nosniff 등 나머지 헤더를 건다.
