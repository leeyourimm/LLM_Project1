# ADR 0002: 답변 모델은 Ollama 로컬 모델

- 상태: 채택
- 관련 코드: `src/dartrag/answer/llm.py`, `src/dartrag/factory.py`, `.env` 의 `OLLAMA_URL`, `LLM_MODEL`

## 맥락
- 설계서(docs/design.md 14절)는 상용 API 와 모델 라우팅을 기본으로 잡았지만, 실제 사용자는 혼자 또는 소수이고 수익을 내지 않는다. 질문 수에 비례하는 API 비용을 감당할 이유가 없다.
- 질문과 대화 기록은 개인정보에 가깝다. 개인정보처리방침에 "질문을 외부 AI 회사로 보내지 않는다"고 약속하려면 모델이 서버 안에 있어야 한다.
- 답의 정확도는 모델 크기보다 검색, 인용·숫자 검증, 코드 계산(ADR 0004)에 더 크게 좌우된다. 8B 급 모델로도 "근거 발췌를 옮겨 적는" 일은 충분히 한다.

## 결정
- 기본 답변 모델은 Ollama 로 띄운 `qwen3:8b`. `LLM` 프로토콜(`chat`, `stream`)만 구현하면 다른 모델로 바꿀 수 있게 둔다.
- 재현성을 위해 `temperature=0`, 추론 모드(`think`)는 끄고 혹시 붙은 `<think>…</think>` 는 지운다. 문맥 길이는 `num_ctx=16384`.
- Mac 에서는 GPU(Metal)를 쓰려고 Docker 가 아니라 Ollama 앱으로 실행한다.
- 변경점 요약, 비교 설명, PDF 요약도 같은 모델을 쓰고, 모델이 꺼져 있으면 LLM 없이 만든 결과(코드가 찾은 변경 목록 등)로 대신한다.

## 결과와 트레이드오프
- 질문당 비용이 0 이고 질문이 서버 밖으로 나가지 않는다.
- 응답이 느리다 (CPU 서버에서 수십 초). 그래서 스트리밍(SSE), 답변 캐시(정확히 같은 질문·뜻이 같은 질문), 요청 한도(`rate("ask")`)를 함께 둔다. 배포 기준의 지연 기준도 `max_latency_p50_s = 45` 로 넉넉하다.
- 작은 모델은 숫자 자릿수·단위를 자주 틀린다. 숫자 검증기와 재무 DB 값 주입으로 보완한다 (ADR 0004).
- 모델을 바꾸면 답변 품질이 바뀌므로, 평가를 다시 돌려 기준선을 올려야 CI 를 통과한다 (ADR 0007).
