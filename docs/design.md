# DART 공시 분석 서비스 설계서 (출시 가능한 품질 기준)

> 목표: 수익은 내지 않되, **실제 사용자에게 공개해도 될 품질**의 공시 분석 서비스
> 원칙: 시간 제약 없이 필요한 기능과 품질 장치를 모두 포함하고, 단계별로 쌓아 올린다

---

## 1. 서비스 개요
상장사 공시(사업보고서, 분기·반기보고서, 주요사항보고서, 지분공시)를 수집해서
**근거를 대며 답하고, 수치를 정확히 보여주고, 변화가 생기면 알려주는** 서비스.

**대상 사용자**: 개인 투자자, 취업 준비생(기업 분석), 기업 실무자(경쟁사·거래처 모니터링)

**하지 않는 것**: 매수·매도 추천, 목표 주가, 수익률 예측 (투자자문 규제 회피 + 신뢰성)

## 2. 전체 기능 목록
| 구분 | 기능 | 설명 |
|---|---|---|
| 탐색 | 기업 검색 | 회사명, 약칭, 영문명, 종목코드로 검색 (예: "하이닉스", "000660") |
| 탐색 | 기업 대시보드 | 개요, 사업 부문, 핵심 재무 지표, 최근 공시, 변경점 요약을 한 화면에 |
| Q&A | 근거 기반 질의응답 | 모든 문장에 원문 출처 링크, 근거 없으면 "확인되지 않음" |
| Q&A | 멀티턴 대화 | "그럼 작년은?"처럼 이어지는 질문의 회사·기간 맥락 유지 |
| 수치 | 재무 조회·추이 | 계정별 수치, 증감률, 분기/연간 추이 차트 |
| 수치 | 기업 비교 | 2~5개사 지표 비교 표와 차트, 사업 구조 비교 서술 |
| 변화 | 변경점 감지 | 새 보고서를 직전 보고서와 섹션별 비교 → 새 리스크, 사라진 사업, 바뀐 수치 요약 |
| 변화 | 주요 공시 요약 피드 | 유상증자, 최대주주 변경, 소송, 감사의견 등 수시공시를 즉시 요약 |
| 알림 | 관심 기업 알림 | 등록 기업의 중요 공시·변경점을 이메일/텔레그램/웹 푸시로 전송 |
| 리포트 | 기업 분석 리포트 | 한 기업의 사업·재무·리스크를 정리한 문서 생성, PDF 다운로드 |
| 계정 | 로그인, 관심 기업, 대화 기록 | |
| 피드백 | 답변 평가 버튼 | 👍/👎 + 사유 → 품질 개선 데이터로 활용 |

## 3. 시스템 아키텍처
```
[수집 워커] ──> [원문 저장소(S3/MinIO)] ──> [파싱·정규화 워커]
     │                                         │
 OpenDART API                    ┌─────────────┼──────────────┐
 (스케줄 + 신규공시 폴링)          ▼             ▼              ▼
                           [Postgres]    [Qdrant 벡터]   [OpenSearch BM25]
                           재무·메타·사용자   dense+sparse     nori 형태소
                                 └──────────┬──────────────┘
                                            ▼
                      [FastAPI] ── [에이전트 오케스트레이터] ── [LLM 게이트웨이]
                          │                 │ tools                (모델 라우팅,
                          │                 ├ search_filings        캐싱, 재시도)
                          │                 ├ get_financials
                          │                 ├ compute (계산기)
                          │                 ├ compare_companies
                          │                 └ list_filings
                          ▼
                  [Next.js 웹] / [알림 워커]
관측: Langfuse(LLM 트레이스) · Prometheus/Grafana · Sentry
작업 큐: Redis + Celery (또는 Temporal)
```

## 4. 데이터
### 수집 범위
- 전 상장사 (KOSPI, KOSDAQ, 약 2,600개사), 2015년 이후
- 정기공시: 사업·반기·분기보고서 원문
- 주요사항보고서, 지분공시, 감사보고서 의견
- 재무: OpenDART 재무제표 API + XBRL 재무 데이터
- (선택) KRX 시세, 뉴스 — 각 제공처 이용약관 확인 후

### 정확성 장치
- **정정공시**: 같은 기간 보고서는 최신 정정본을 기준으로, 이전 버전은 이력으로 보관
- **단위·통화 통일**: 원/천원/백만원, 외화 표기 → 원 단위 정수로 저장, 원본 단위도 기록
- **연결/별도 구분**: 기본은 연결, 둘 다 저장
- **계정과목 표준화**: 회사마다 다른 계정명("영업이익", "영업이익(손실)")을 IFRS 표준 코드로 매핑, 매핑 실패는 검수 큐로
- **회계 기간 정규화**: 결산월이 12월이 아닌 회사 처리, 분기 누적값 → 분기 단독값 변환
- **데이터 검증 규칙**: 자산 = 부채 + 자본, 전년 대비 급변 탐지, 실패 시 알림

### 수집 운영
- 원문은 모두 자체 저장 (재처리, API 한도 대응)
- 신규 공시 폴링 → 30분 이내 반영, 실패 재시도와 알림
- 증분 처리: 바뀐 문서만 다시 파싱·인덱싱

## 5. 문서 처리
- XML 파싱으로 **섹션 계층** 보존 (I. 회사의 개요 > 1. 회사의 개요 > ...)
- **표 처리**: 셀 병합 해제, 표 제목·단위·기준일을 함께 저장, 마크다운(검색용)과 JSON(정확 조회용) 두 형태 보관
- 각주를 해당 표·문단과 연결
- **청킹**: 섹션 경계 기준, parent-child 구조(작은 청크로 검색, 큰 섹션으로 답변 맥락 제공)
- **Contextual retrieval**: 각 청크 앞에 "회사 / 연도 / 보고서 / 섹션 경로" 맥락 문장 추가
- **반복 문구 처리**: 매년 동일한 상투 문구는 중복 제거하거나 가중치 낮춤
- 메타데이터: 회사, 종목코드, 연도, 분기, 보고서 종류, 섹션 경로, 접수번호, 정정 여부, 원문 URL

## 6. 검색
1. **질의 이해**: 회사명·별칭 → 종목코드 정규화, 기간 해석("작년", "최근 3분기", "코로나 이전"), 질문 유형 분류
2. **질의 재작성·분해**: 복합 질문을 하위 질문으로 나누기 ("A와 B 비교" → A 검색 + B 검색)
3. **하이브리드 검색**: BM25(OpenSearch nori) + dense(bge-m3) + sparse, RRF로 결합
4. **메타데이터 필터**: 회사·기간·보고서 종류로 사전 필터 (다른 회사 문서 혼입 방지)
5. **리랭킹**: bge-reranker-v2-m3 (또는 상용 리랭커와 비교)
6. **최신성 가중**: 같은 내용이면 최신 보고서 우선

## 7. 답변 생성 (에이전트)
- **라우팅**: 질문 유형에 따라 툴 선택. 서술형은 검색, 수치는 DB, 복합은 둘 다
- **툴 설계**: 자유 SQL 대신 **정해진 파라미터 툴**(`get_financials(종목, 기간, 계정, 연결여부)`)로 안전성 확보
- **계산은 코드로**: 증감률, 비율, 합계는 LLM 암산 금지, `compute` 툴 사용
- **숫자 검증기**: 최종 답변의 모든 숫자를 DB 값·근거 원문과 대조, 불일치 시 재생성 또는 해당 문장 제거
- **인용 검증기**: 인용한 청크가 실제로 그 문장을 뒷받침하는지 NLI/LLM으로 확인
- **거절 정책**: 근거 부족, 투자 추천 요청, 범위 밖 질문은 정중히 거절하고 가능한 대안 제시
- **스트리밍 응답**, 출처는 답변과 함께 카드로 표시
- **프롬프트 버전 관리**: 프롬프트를 코드처럼 버전 관리하고 평가 통과 후 배포

## 8. 변경점 감지 파이프라인
1. 새 보고서 수집 → 직전 동일 유형 보고서와 섹션 매칭
2. 섹션별 텍스트 diff + 표 수치 diff
3. 의미 없는 변화(날짜, 문구 순서) 필터링
4. LLM이 "새로 생긴 리스크 / 사라진 내용 / 의미 있는 수치 변화"로 분류·요약, 각 항목에 원문 링크
5. 중요도 점수 → 임계값 넘으면 관심 사용자에게 알림

## 9. 평가 체계
### 오프라인 평가셋 (300문항 이상, 계속 확장)
| 유형 | 비중 | 예시 |
|---|---|---|
| 서술형 | 25% | 주요 사업 부문, 리스크 요인 |
| 수치 조회 | 25% | 특정 연도 영업이익 |
| 비교·추이 | 15% | 3년 매출 추이, 2개사 비교 |
| 복합 추론 | 10% | 수치 변화 + 원인 설명 |
| 변경점 | 10% | 작년 대비 새로 생긴 리스크 |
| 답 없음 | 10% | 공시에 없는 내용 |
| 적대적 | 5% | 투자 추천 유도, 프롬프트 인젝션 |

- 문항 작성: LLM 초안 → 원문 대조 검수 → 가능하면 금융 지식 있는 사람 2차 검수
- 정답, 근거 위치(접수번호 + 섹션), 허용 오차를 함께 기록

## 11. 보안, 안전, 법적 고지
- **투자자문 규제**: 정보 제공으로 한정, 추천 요청은 거절, 모든 화면에 "투자 권유 아님" 고지. 공개 전 법률 자문 권장
- **데이터 약관**: OpenDART, KRX 등 각 데이터 이용약관과 호출 한도 준수
- **프롬프트 인젝션**: 문서 내용은 데이터로만 취급, 시스템 지시와 분리, 툴 권한 최소화
- **개인정보**: 최소 수집(이메일), 처리방침, 대화 기록 보관 기간과 삭제 기능
- **남용 방지**: 인증, 사용자별 요청 한도, 봇 차단
- 비밀키는 시크릿 매니저로 관리

## 12. 성능·비용 최적화
- 시맨틱 캐시 (같은 의미의 질문 재사용), 기업 대시보드는 사전 생성 후 캐시
- 프롬프트 캐싱, 질문 난이도별 모델 라우팅 (분류·재작성은 작은 모델, 최종 답변은 큰 모델)
- 임베딩·변경점 요약은 배치 처리
- LLM 게이트웨이에서 재시도, 타임아웃, 대체 모델(fallback)

## 13. 프론트엔드 UX
- 답변 옆에 근거 원문 패널, 해당 문단 하이라이트
- 수치는 표·차트로, 단위와 기준(연결/별도, 기간)을 항상 표시
- 답변 신뢰도 표시 (근거 개수, 최신 공시 여부)
- 모바일 대응, 다크모드, 접근성

## 14. 기술 스택
| 영역 | 선택 |
|---|---|

| 관측 | Langfuse, Prometheus, Grafana, Sentry |
| 배포 | Docker, GitHub Actions, 클라우드 VM → 필요 시 Kubernetes |
| 인프라 코드 | Terraform |
